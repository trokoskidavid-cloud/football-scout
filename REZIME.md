## 1. Идеја

FootballScout е платформа за **скаутирање фудбалери**. Скаутите (регистрирани корисници) додаваат играчи што ги следат,
пишуваат **scouting извештаи** со пет оценки (техника, физичка подготовка, тактика, ментална сила, потенцијал) и препорака
(Потпиши / Следи / Одбиј), ги поврзуваат со конкретни **натпревари**, а апликацијата автоматски пресметува просеци,
статистики и ги прикажува на графикони. Колегите дискутираат преку **коментари**, а клубот (администраторот) добива
известување по е-пошта кога некој играч е препорачан за потпишување.

Проектот не е копија на постоечко решение (продавница, форум…) – фокусот е на **оценување и споредба** на играчи
врз основа на повеќе независни извештаи и реални податоци од натпревари.

**Надворешен извор:** [TheSportsDB](https://www.thesportsdb.com) – јавен REST API со податоци за професионални фудбалери и клубови.
Скаутот пребарува вистински играч, а апликацијата ги увезува биографијата, фотографијата, националноста, позицијата и клубот
(и го креира клубот ако не постои). Тоа се податоци што нашата база примарно ги нема.
Се користи бесплатниот клуч на TheSportsDB, кој враќа по еден резултат за пребарување, па се пребарува по целото име на играчот (пр. „Eljif Elmas“).

## 2. Модел на податоци (MongoDB – 7 колекции)

| Колекција | Опис | Зависи од |
|---|---|---|
| **users** | корисници, улога `user`/`admin`, bcrypt лозинка | – |
| **clubs** | клубови (лига, стадион, грб, externalId) | – |
| **players** | играчи, позиција, статус на следење | **clubs**, users (createdBy) |
| **matches** | натпревари + вгнездена статистика по играч (минути, голови, асистенции, оцена) | **clubs**, **players** |
| **reports** | scouting извештаи, 5 оценки, автоматски просек | **players**, **users**, matches |
| **comments** | коментари на извештаи | **reports**, **users** |
| **activities** | историја на сите активности | users |

Каскадно бришење: бришење играч → неговите извештаи → нивните коментари; бришење извештај → коментарите; бришење натпревар → референците во извештаите.

**Иницијални податоци** (страница `/db`): 4 корисници, 6 клубови (Вардар, Работнички, Струга, Академија Пандев, Real Madrid, FC Barcelona), 24 играчи, 9 натпревари (вклучително два Ел Класико), 20 scouting извештаи и коментари. Македонските играчи се измислени; за играчите на Real Madrid и Barcelona пазарните вредности и оценките се демонстративни.

## 4. Исполнети функционални барања

- **Три типа корисници** – гостин, регистриран корисник (скаут), администратор; различни погледи и дозволи (JWT + `authorize`).
- **Е-пошта** (nodemailer) – при регистрација, нов коментар на твој извештај, нова препорака „Потпиши“ (до админите).
- **Графикони** (Chart.js) – радар на оценки, линиски графикон на форма, doughnut и bar графикони на статистиката.
- **Напредни HTML компоненти** – `range`, `date`, `multiple select`, `btn-check` радио групи, `progress`, `details/summary`.
- **Генерирање извештаи** – CSV извоз на scouting извештаите (со BOM за Excel), print-friendly приказ на извештај.
- **Зумирање** – модален прозорец со зум +/- на фотографијата на играчот.
- **Историски преглед** на активностите (колекција `activities`).
- **Интеракција меѓу корисници** – коментари на извештаи со известување по е-пошта.
- **Деловни правила** – препорака „Потпиши“ автоматски го префрла играчот во „потесен избор“; просекот се пресметува на серверот.

## 6. Серверска страна (Дел 2 и 3)

- MVC структура: `models/`, `controllers/`, `routes/`, `middleware/`, `services/`.
- REST API со соодветни методи (GET/POST/PUT/DELETE) и статуси (200, 201, 204, 400, 401, 403, 404, 409, 502).
- Централизирано справување со грешки (`middleware/errorHandler.js`) – Mongoose ValidationError, CastError, дупликати.
- Swagger: JSDoc `@openapi` коментари → `swagger-jsdoc` → `/api/swagger.json` → `swagger-ui-express` на `/api/docs/`.
- Локална база (Docker) vs продукциска (Atlas) – автоматски според `NODE_ENV`.
- `docker-compose up` ги стартува MongoDB и апликацијата и ја полни базата.

## 7. Тестирање во прелистувачи

Апликацијата користи Bootstrap 5 и стандардни веб API-ја, па распоредот е конзистентен. При тестирање обрнете внимание на:

| Прелистувач | Верзија | Забелешки (пополнете по тестирање) |
|---|---|---|
| Google Chrome | | |
| Mozilla Firefox | | |
| Safari / Microsoft Edge | | |

Типични разлики што вреди да се проверат: изгледот на `<input type="date">` (Safari/Firefox прикажуваат различен календар),
стилот на `<input type="range">` лизгачите, `<select multiple>` на мобилни уреди (се отвора како листа), и печатењето на извештај (`@media print`).
Маските и SPA-то се responsive (Bootstrap): мобилен (< 768px, картички наместо табели), таблет (768–992px), десктоп (≥ 992px).
